# 前端施工图（F0–F5）

> 这套文件和后端 `docs\实现分块\` 是同一个套路：**一次只做一块，做完对着验收清单打勾，再下一块。**

## 1. 文件清单与顺序

| 文件 | 内容 | 依赖 | 估时 | 状态 |
|---|---|---|---|---|
| `F0-骨架.md` | 路由 + 布局 + 接口封装 + 全局样式 | 无 | 半天 | ⬜ |
| `F1-上传页.md` | 拖拽上传 + 进度 + 审计中 + 结果卡 | F0 | 1 天 | ⬜ |
| `F2-任务列表.md` | 表格 + 状态 + 轮询 + 跳转 | F0 | 半天 | ⬜ |
| `F3-报告页.md` | 合规率 + 图表 + 明细高亮 + 三按钮 | F1/F2 | 1.5–2 天 | ⬜ |
| `F4-规则库.md` | 统计卡 + 分类图 + 表格 + 抽屉 | F0 | 1 天 | ⬜ |
| `F5-收尾.md` | 空状态 / 错误提示 / 构建 / 整合成单 jar | 全部 | 半天 | ⬜ |

依赖关系：**F0 → F1 → F2 → F3 → F4 → F5**，严格串行。总计 5–6 天。

## 2. 每份文件的结构（固定七段）

1. 目标 / 前置 / 产出 / 估时 / 验收标准
2. 这一块在回答什么问题
3. 涉及文件表（新建还是改）
4. 操作步骤（**完整可直接粘贴的代码**）
5. 验收打勾清单（都是"看得见"的现象）
6. 卡住怎么办（症状 → 原因 → 处理）
7. 做完记录（写完自己补一行）

## 3. 在 Trae 里怎么用（每次只喂一个文件）

**第一条消息（只读不写）**

```
先不要改任何文件。

读这三份：
1. docs/实现分块/F0-骨架.md
2. README.md
3. .trae/rules/project_rules.md

回报三件事：
（1）F0 的「涉及文件」表里有几个文件，分别是什么
（2）api.js 的 baseURL 是什么
（3）F0 的验收标准有哪几条
```

**第二条消息（开始实现）**

```
按 F0-骨架.md 实现，一次只做一个步骤，做完停下来给我看代码。

约束：
- 只改「涉及文件」表里列出的文件，不要动别处
- 代码直接照抄施工图里的实现，不要自己改接口名、字段名
- 每个文件顶部保留六段中文注释
- 不要跑 npm install，依赖已经装好了
```

**第三条消息（验收）**

```
现在按「验收打勾清单」逐条给我证据：
每一条说明在哪个文件、哪一行能证明它，不要只说"已完成"。
```

## 4. 铁律（四条，任何一块都适用）

1. **字段名照抄后端**：`startLine`、`codeSnippet`、`complianceRate` 这些是后端 JSON 里的原名，前端不要 camelCase 转下划线，也不要改名。
2. **`/api` 开头，不写域名**：`vite.config.js` 已经代理到 8080。
3. **上传/审计请求 timeout ≥ 120000**：后端是同步审计，一次十几秒到一分钟。
4. **错误信息直接展示 `error` 字段**：后端已经返回中文原因，前端不要自己编提示语。
